# Exchange From Scratch

A limit order book and matching engine in C++20, built as the core of a small exchange. v0 is one symbol on one thread: price-time priority matching, five order types, cancel and modify, fixed-point prices, an event-sourced interface where every input and output is a logged event, an L2 market-data feed, and a deterministic replay tool. Correctness is checked by differential fuzzing against a brute-force reference matcher on millions of random orders.

Project 06 of the deep-dive series, in the Trading thread. Later projects (07 to 10) are meant to consume its event and market-data streams.

## What it does

* Order types: limit (good till cancel), market, IOC, FOK, post-only
* Cancel, and modify with the usual rule: reducing size at the same price keeps queue position, increasing size or changing price loses it
* Prices are `int64` ticks and quantities `int64` lots; no floating point in the engine
* Every input (`N`, `C`, `M`) produces a deterministic sequence of output events (`ACCEPTED`, `REJECTED`, `TRADE`, `CANCELED`, `MODIFIED`, `L2`), each tagged with the input's sequence number
* L2 updates are coalesced per input and carry absolute level quantities
* `exch replay` replays an input log and prints a 64-bit digest of the output stream; `exch verify` checks a replay against a saved output log or digest

See [DESIGN.md](DESIGN.md) for the architecture, data structures and invariants, and [DEVLOG.md](DEVLOG.md) for how it was built and measured.


## Build

Requirements: CMake 3.24+, Ninja, a C++20 compiler. GoogleTest is fetched by CMake at configure time. Release numbers use Apple clang 17 at `-O2`.

```sh
# Release (-O2): engine, CLI, tests, benchmarks
cmake --preset release
cmake --build --preset release

# Debug with AddressSanitizer + UndefinedBehaviorSanitizer
cmake --preset asan
cmake --build --preset asan
```

The `asan` preset uses Homebrew LLVM (`/opt/homebrew/opt/llvm/bin/clang++`) because Apple clang 17's ASan runtime hangs at startup on macOS 26.5, even for an empty `main` (details in DEVLOG). Install it with `brew install llvm`, or edit the preset to point at another clang.

Without presets:

```sh
cmake -S . -B build/release -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build/release
```

## Test

```sh
ctest --preset release          # about 1 minute
ctest --preset asan -j2         # about 2 minutes on an idle M4 Pro; differential tests dominate
```

The suite has 37 GoogleTest cases plus two CLI tests (a gen, replay, verify round trip and a golden-file replay of `examples/basic.log`).

Longer differential fuzzing against the reference matcher, in Release:

```sh
./build/release/exch fuzz --n 1000000 --seed 1 --seeds 2           # 2M events
./build/release/exch fuzz --n 300000 --seed 21 --width 200 --max-live 5000   # deeper book
scripts/mutation_test.sh 200000   # plants 6 known bugs and checks the fuzzer catches each
```

## Benchmark

```sh
scripts/run_bench.sh 3 300000 3000000         # 3 reps x 3 id-index variants
python3 -m venv .venv && .venv/bin/pip install matplotlib
.venv/bin/python scripts/plot_bench.py results/bench
```

`bench_engine` measures add, cancel and match latency in a steady-state book of 1k to 1M resting orders, burst throughput per path, and throughput on a random mixed flow. Raw CSVs, per-run stdout, machine info and plots land in `results/bench/`.

## Run

```sh
./build/release/exch replay --in examples/basic.log --out /tmp/basic.out
./build/release/exch gen --n 1000000 --seed 2026 --out /tmp/in.log
./build/release/exch replay --in /tmp/in.log --out /tmp/out.log --l2 /tmp/l2.csv --trades /tmp/trades.csv
./build/release/exch verify --in /tmp/in.log --expect /tmp/out.log
```

Input log format, one event per line (`#` starts a comment):

```
N <id> <B|S> <LMT|MKT|IOC|FOK|POST> <price_ticks> <qty_lots>
C <id>
M <id> <new_price_ticks> <new_qty_lots>
```

No external dataset is needed. All order flow is generated by `exch gen` from a seed, so large logs are never committed; regenerate them instead.

## Headline results

All numbers are from runs in this session on an Apple M4 Pro (14 cores, 48 GB), macOS 26.5, Apple clang 17, `-O2`. The machine was shared with other heavy jobs the whole time (1-minute load average 172 to 352 on 14 cores, logged in `results/bench/machine.txt`), so wall-clock numbers and tail percentiles are inflated by scheduling. Throughput is also reported in thread CPU time for that reason.

| Metric | Value | Source |
|---|---|---|
| add latency p50 / p99 / p99.9, 10k resting | 167 / 541 / 3208 ns | `results/bench/summary_latency.csv` |
| cancel latency p50 / p99 / p99.9, 10k resting | 209 / 916 / 7333 ns | same |
| match latency p50 / p99 / p99.9, 10k resting | 84 / 542 / 1583 ns | same |
| cancel p50, 1M resting | 459 ns (std::unordered_map index: 750 ns) | same |
| mixed random flow, median of 9 runs | 13.1 M events/s CPU time (6.5 M new orders/s), 4.8 M events/s wall | `results/bench/summary_throughput.csv` |
| burst throughput, 1M orders | add 4.4 M/s, cancel 2.2 M/s, match 3.8 M/s (CPU time) | `results/bench/summary_burst.csv` |
| differential fuzz | 8.3 M random events, 0 divergences | `results/fuzz_*.txt` |
| planted bugs caught by the fuzzer | 6 of 6 | `results/mutation.txt` |
| replay determinism, 1M events | identical digest `fa2ff178540c7510` on two runs, line-for-line verify OK | `results/replay/` |

Latencies are medians across 3 repetitions. The timer on this machine ticks every 41.7 ns, so every latency is a multiple of it.

### What v0 does not do

Nothing from the v0 list was cut. These are simplifications inside v0 that are called out so they are not mistaken for features:

* One symbol per engine instance.
* Order ids are client supplied and only need to be unique among resting orders; a real gateway would assign exchange ids.
* A modified order always becomes a plain limit order, so a post-only order modified across the spread trades instead of being rejected.
* No accounts, so no self-trade prevention and no risk checks.
* The event log is text. It is readable and diffable but not fast to parse.
